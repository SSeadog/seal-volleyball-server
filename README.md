# SealVolleyball

2:2 실시간 대전 배구 게임. Colyseus 기반 WebSocket 멀티플레이를 통해 웹(Web) 환경에서 동기화된 경기를 제공합니다.

## 제작 정보
- 장르: 2:2 실시간 대전 배구
- 제작 인원: 1명
- 제작 기간: 약 2개월
- 사용 엔진: UnityEngine, Colyseus(JavaScript)
- 플랫폼: web
- 배포(itch.io): https://sseadog.itch.io/seal-volleyball

## 핵심 개발 내용

### 1. 실시간 멀티플레이 네트워크 아키텍처 설계
Colyseus 기반 WebSocket 멀티플레이 서버를 구축하고, `LobbyRoom` / `GameRoom`으로 멀티룸 아키텍처를 분리했습니다. 매칭 큐 기반 4인 자동 매칭 및 게임 룸 생성 로직을 구현했습니다.

### 2. Input 기반 네트워크 동기화 시스템 구현
클라이언트 입력을 서버로 전송하고, 서버에서 시뮬레이션하고, 시뮬레이션한 상태를 동기화하는 방식으로 설계했습니다.

### 3. Tick 기반 게임 동기화 시스템 구현
클라이언트에서 입력을 서버로 전송할 때 Tick 정보를 담아서 보내고 서버에서는 받은 Tick 정보를 기반으로 Input을 처리하도록 하였습니다.

### 4. 네트워크 지연(Latency) 대응
네트워크 지연으로 인한 패킷 지연을 최대 3 Tick까지 허용했습니다. 서버는 동기화 안정성을 위해 2 Tick 지연된 과거를 기준으로 시뮬레이션하도록 구성했습니다.

### 5. 물리 기반 공 및 충돌 시뮬레이션 구현
서버 기반으로 공/플레이어/네트 충돌을 포함한 물리 시뮬레이션을 구현했습니다. 이를 기반으로 점수 판정을 서버에서 처리하도록 하였습니다.

## 시행착오 / 문제점

### 네트워크 동기화/판정 이슈
- 배구공의 바닥 충돌 판정이 서버 기준이라, 클라이언트에서 공이 땅에 닿는 순간을 보고 입력하면 이미 실점 처리되는 문제가 있었습니다.
  - 이를 완화하기 위해 공 판정에 2 Tick 유예를 두었습니다. 즉, 바닥 접촉 후 점수 계산은 2 Tick 뒤에 수행하고, 그 사이 공을 다시 띄우면 바닥 접촉 정보를 초기화해 랠리를 계속 진행할 수 있도록 했습니다.
- 동기화 로직을 입력(Input) 기반 동기화 + 클라이언트 예측 이동으로 구성했는데, 네트워크 지연과 Jitter로 인해 클라이언트 위치 오차가 누적되는 문제가 있었습니다.
  - 서버 위치를 수신해 점진적으로 후보정하는 로직을 추가했습니다.
- Tick 기반 입력 동기화에서는 Jitter로 Tick이 튀는 경우가 있었습니다.
  - 동기화 안정성을 위해 너무 늦게 도착한 입력 데이터는 폐기하도록 처리했습니다.
  - 늦게 도착한 데이터를 지연 정도에 맞춰 재계산 후 반영하는 방식도 검토했지만, 프로젝트 규모와 일정 대비 구현 복잡도가 높아 적용하지 않았습니다.

## 향후 개선 방향
- 지연 시간 기반 위치 보간(Interpolation) 도입으로 Jitter 대응 품질을 향상
- Tick 동기화 안정성 및 동기화 오류 디버깅 도구 강화
- 서버 검증(입력/행동) 강화 및 예외 케이스 처리 확장
